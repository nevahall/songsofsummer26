# Top 10 Songs of the Summer — Jekyll Site

A modern, responsive Jekyll starter site for a Markdown-powered summer-song countdown. It is designed to publish directly through GitHub Pages.

## Project structure

```text
.
├── _config.yml              # Jekyll configuration and songs collection
├── _layouts/
│   ├── default.html         # Shared site shell
│   └── song.html            # Layout for every song page
├── _songs/                  # Your 10 Markdown song pages
├── assets/css/style.css     # Responsive visual design
├── index.md                 # Home page
├── Gemfile                  # GitHub Pages dependencies
└── .gitignore
```

## Adding or editing song content

Each file in `_songs/` is a Markdown document. The starter files are named `song-01.md` through `song-10.md`. Keep the `rank` values from 1 through 10 so the home page displays the countdown in order.

A song file uses YAML front matter at the top, followed by Markdown:

```yaml
---
title: "Song title"
performer: "Performer name"
rank: 1
season: "Summer 2026"
layout: song
---
```

After the closing `---`, write your review in Markdown. Use two or more paragraphs for the review. The song layout already provides the title, performer, image placeholder, and rating line.

### Adding an image

The design includes a visual placeholder so the site works immediately. To use an image:

1. Create an `assets/images/` directory.
2. Add your image, for example `assets/images/song-01.jpg`.
3. In the song Markdown file, replace the placeholder block with:

```html
<img class="cover-placeholder cover-placeholder--large"
     src="{{ \"/assets/images/song-01.jpg\" | relative_url }}"
     alt="Description of the image">
```

Only use images you have permission to publish. Add a useful, specific `alt` description.

### Updating the rating

In `_layouts/song.html`, replace `☆☆☆☆☆` with the rating you want to show, such as `★★★★☆`. If you want a different rating on every page, add a `rating` value to each song's front matter and update the layout to use `{{ page.rating }}`.

### Customizing the home page

Edit `index.md` to add your project introduction. The home page automatically creates the song cards by looping through the documents in `_songs/`.

## Run the site locally

Install Ruby and Bundler, then run:

```bash
bundle install
bundle exec jekyll serve --livereload
```

Open `http://localhost:4000` in a browser. Stop the server with `Ctrl+C`.

If you do not want live reload, use:

```bash
bundle exec jekyll serve
```

## Publish with GitHub Pages

1. Create a new GitHub repository.
2. Copy all files from this project into the repository root.
3. Commit and push the files:

```bash
git init
git add .
git commit -m "Create summer songs site"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

4. In GitHub, open **Settings → Pages**.
5. Under **Build and deployment**, choose **Deploy from a branch**.
6. Select the `main` branch and the `/ (root)` folder, then click **Save**.
7. Wait for the GitHub Pages workflow to finish. GitHub will display the published URL in the Pages settings.

For a project site, the configured empty `baseurl` will be overridden by GitHub Pages during its build. If you test with a custom deployment setup, set `url` and `baseurl` in `_config.yml` as needed.

## GitHub Pages notes

- Keep Markdown filenames lowercase and use hyphens instead of spaces.
- Commit `_config.yml`, `_layouts/`, `_songs/`, `assets/`, and `index.md`.
- Do not commit `_site/`; it is generated by Jekyll and is already ignored.
- If a build fails, inspect the repository's **Actions** tab for the exact Jekyll error.
- GitHub Pages rebuilds the site after changes are pushed to the selected branch.
